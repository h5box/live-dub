# live-dub 调研：中文语音合成（TTS）选型（v2：按 09-30 需求调整）

> 本版按 09-30 的需求调整重点：
> - 先做英语，克隆主播音色是必需项（英语参考、中文输出）；发布会多人时每人各自克隆，说话人 ID 由上游给出。
> - 配音采用同传式，原声整体压低，中文盖在上面。
> - 全部本机跑，TTS 只能分到约 4–6 GB 显存；云端只作兜底。
>
> 我只做了网络调研，没有在本机实测。方括号是第 6 节的来源编号，标「推测」的是我的推断。RTF = 合成耗时 ÷ 音频时长，越小越快。

## 1. 结论先行

- **首选：IndexTTS-2.5（本地）。** 它是候选里唯一能把音色参考和情绪参考当作两段音频分开输入的：`spk_audio_prompt` 给音色，`emo_audio_prompt` 或 8 维情绪向量给情绪 [1][4][6]。它还有模型内的时长倍率 `duration_factor` [1][6]。在与 5060 Ti 同级的 A10 上，T2S 加 S2M 的 RTF 是 0.136 [3]。许可在门槛以内可以商用 [7]。
  - **硬风险一：** 「英语参考 → 中文输出」的相似度和口音没有任何公开数据。
  - **硬风险二：** 官方给的显存约 6 GB [2]，正好压在预算上限；默认精度是 FP32，要手动开 BF16 [6]。
  - 这两项必须第一轮就测。
- **备选 A：Fun-CosyVoice3-0.5B（本地，Apache-2.0）。**
  - 它是唯一公开了英→中相似度的开源模型：CV3-Eval 上英→中 CER 8.48%、SIM 67.4，好于 CosyVoice2、F5-TTS、Spark-TTS [8]。
  - 它的 `cross_lingual` 模式只把说话人向量交给 LLM，不给参考音频的文本和语音 token [11]。按设计应该更不容易把英语口音带进中文（推测）。
  - 短板：情绪只能用文字指令控制 [12]；在 Windows 上不开 CUDA Graph，4090 都跑不到实时 [15]。
- **备选 B：Qwen3-TTS Base 0.6B/1.7B（本地，Apache-2.0）。**
  - 公开的英→中可懂度最好（CV3-Eval CER 4.77%）[16]；1.7B 显存约 3.9 GB [17]；有只用说话人向量的 `x_vector_only_mode` [18]。
  - 短板：克隆模型不能控制情绪，也没有时长接口 [18]；有人报告把英语音色克隆去说意大利语时带浓重美国口音 [19]；官方实现在 Blackwell 小卡上很慢 [20]，要改用社区的 CUDA Graph 版 [21]。
- **口音兜底路线：** 如果上面三个在英→中都带口音，改成两步：先用中文母语参考音色合成（发音地道，时长也已对齐），再做零样本音色转换，换成主播的音色。可用 OpenVoice V2（MIT）[22] 或 CosyVoice 的 `inference_vc` [12]。相似度会低于直接克隆（推测）。
- **云端兜底：** 百炼 CosyVoice v3.5、豆包声音复刻 2.0、MiniMax speech-2.8 都能复刻，但都要把发言人声音传上云（见 3.6）。

### 1.1 时长对齐打法（同传式）

1. **先按预算定译文字数。** 目标时长 T 取源句开口到收口。原声已经压低，中文比原声晚 ≤0.3 s 收口应该可以接受（推测），但不能压到同一说话人的下一句。
   - 字数上限 N = ⌊(T + 0.3) × v × 0.95⌋。v 是该说话人克隆音色在 1.0 倍速下的实测语速，参考库建好后测一次。
   - 超出上限，先让翻译模块压缩译文。
2. **用自然语速合成一遍。** IndexTTS-2.5 跑完 GPT 就能由语义长度算出自然时长 T0：S2M 的目标帧数 = 语义长度 × 1.72 × `duration_factor` [6]。然后算 r = T / T0。
3. **按 r 分档处理：**
   - 0.85 ≤ r ≤ 1.15：设 `duration_factor = r`，只重跑 S2M。
   - r 在 0.75–0.85 或 1.15–1.25：倍率一半交给模型，一半交给 rubberband R3 [40]。
   - r < 0.75：退回第 1 步重写译文。
   - r > 1.25：不硬拉长，提前收口。
4. **起点对齐。** 配音起点放在源句开口后 0–100 ms。依据是 ITU-R BT.1359 的可察觉阈值：声音超前 45 ms、滞后 125 ms [42]。
5. **其他模型怎么对齐。**
   - CosyVoice3 用 `speed`，它本质上是对 mel 做线性插值 [13]。
   - Qwen3-TTS 只能靠译文预算，再加事后变速。
   - 社区 PR #793 给 IndexTTS 加了按秒指定时长的参数，还没合并，可以参考它的实现 [5]。

## 3. 重点问题与各候选要点

### 3.1 英语参考 → 中文：音色相似度与口音

**公开基准只有 CV3-Eval。** 它的参考音频和目标文本取自 CommonVoice / FLEURS，有意不过滤噪声和长静音 [8]。数据说明跨语种比单语难得多：CosyVoice3-0.5B 在同一基准上，中文单语 CER 3.89%，英→中是 8.48% [8]。

**相似度：** CV3 论文里英→中的 SIM 在 63 到 67 之间，CosyVoice3-0.5B 最高，为 67.4 [8]。Qwen3-TTS 和 IndexTTS 都没有公布跨语种 SIM [16][3]。

**口音：** 没有一家公布「外国口音」的量化指标。间接证据有两条：
- MiniMax-Speech 论文：跨语种合成时，只用说话人编码器（不给参考转写）的 WER 明显低于「参考音频 + 转写」的 one-shot（越南语 0.659 对 1.788），SIM 只是略低（0.692 对 0.725），听感也更自然。作者的解释是韵律不受参考约束 [23]。
- Qwen3-TTS 有用户报告英语音色克隆去说意大利语时带浓重美国口音 [19]。

**推论（推测）：** 把英文参考的语音 token 或转写当作前缀（ICL）的做法，最容易把英语韵律带进中文。只用说话人向量（CosyVoice `cross_lingual`、Qwen3 `x_vector_only_mode`），或走「母语合成 + 音色转换」，可以降低口音，代价是相似度下降。

IndexTTS-2.5 介于两者之间：它不需要参考转写，但 GPT 的说话人条件来自参考音频的 w2v-BERT 语义特征 [6]。会不会串味只能实测。

**测法：** 用本机 ASR 的 CER 作为口音的代理指标，再加中文母语者的口音评分（1–5 分）和说话人相似度。

### 3.2 时长控制

打法见 1.1，这里补充三点：
- IndexTTS 的倍率只作用在 S2M 上，GPT 的输出不变，语速变化由 flow-matching 重新生成。推测比在波形上变速更自然。
- CosyVoice 的 `speed` 是对 mel 做线性插值 [13]。
- Qwen3-TTS 和 GPT-SoVITS 只能事后变速：
  - rubberband R3 处理人声比 R2 好，但更耗 CPU，许可是 GPL [40]；
  - SoundTouch 属于 WSOLA 类算法，有专门的 `-speech` 参数，许可是 LGPL [41]。

0.8–1.3 倍区间的公开主观评分没有找到，需要本机做 ABX。

### 3.3 5060 Ti 这一级卡上的速度和显存

**先给 5060 Ti 定位。** 官网标 5060 Ti 为 128-bit GDDR7 [37]，按 28 Gbps 推算带宽约 448 GB/s（推算）。对比：4090 为 1008 GB/s，4060 Ti 为 288 GB/s [38]；A10 为 600 GB/s，FP16 张量算力 125 TFLOPS [36]。所以 A10 和 4060 Ti 的数字是最接近的参照。

**各模型的粗估：**
- IndexTTS-2.5：A10 上 T2S 0.119 加 S2M 0.017 [3]，4090 整体 0.21 [1]。本机整体粗估 0.2–0.45（推测）。
- GPT-SoVITS：4060 Ti 上 0.028 [27]，是唯一有同级卡实测数据的。
- Qwen3-TTS 0.6B：CUDA Graph 版在 T4 上 1.07 倍实时 [21]。本机粗估 2–3 倍实时（推测）。
- VoxCPM1.5：4090 上 0.15 [24]。本机约 0.3（推测）。

**Windows / WSL 上的坑：**
- CosyVoice3 在 4090 + Windows（WDDM 驱动模式）上，eager FP16 的 RTF 是 2.4–3.3。主因是 WDDM 下 kernel 启动延迟比 Linux 高一个数量级，另外还有 CPU 瓶颈、onnxruntime 只走 CPU、FP16 不稳定。开了 CUDA Graph 后降到 0.76–0.95 [15]。
- Qwen3-TTS 官方实现在 RTX 5050 上 GPU 利用率只有约 15% [20]。
- IndexTTS2 在 5090（Windows / WSL2）上合成 2.84 s 短句，RTF 1.16 [33]；在 3060 12 GB（Windows）上 RTF 13 [34]。

结论：自回归 TTS 一律用 CUDA Graph、vLLM 或 TensorRT 的实现。WSL2 同样经过 Windows 驱动，推测有同类开销；NVIDIA 只说把活批量排到 GPU 上可以接近原生性能 [39]。WSL 和原生 Windows 两边都要测。

**显存与加速：**
- IndexTTS 的 Qwen 情绪模型只在 `use_qwen_emo=True` 时加载 [6]，不要开。
- IndexTTS-2.5 官方的 vLLM 配方要求 vLLM 0.27+ [31]。
- 社区的 index-tts-vllm 称，IndexTTS2 在 4090 上 RTF 从约 0.3 降到约 0.1，5 GB 显存可以承受约 16 路并发 [32]。
- 有人报告用 vLLM-Omni 部署后语速异常地快（#789，没有细节）[53]，上线前要测。

**吞吐估算（推测）：** TTS 占用 ≈ RTF × 有声比例。发布会的有声比例按 0.8 算，RTF 0.3 时 TTS 约占 0.24 个实时。

### 3.4 参考音频怎么选

**长度：** 建议取 6–12 s 连续语音（推测最稳），不足 3 s 的不用。各模型的相关限制：
- IndexTTS 两路参考都只取前 15 s [6]；
- F5-TTS 建议参考短于 12 s，末尾留约 1 s 静音 [29]；
- CosyVoice 不支持从超过 30 s 的音频提取语音 token [11]；
- Qwen3-TTS 称 3 s 即可克隆 [18]。

**干净度：** 可以照搬 Emilia-Pipe，它是专门从网络视频里做 TTS 训练数据的流水线 [28]：
1. 用 UVR-MDX-Net Inst 3 分离人声；
2. 用 pyannote 3.1 做说话人分离；
3. 用 Silero-VAD 切成 3–30 s 的片段；
4. 只保留 DNSMOS P.835 OVRL 大于 3.0 的片段（原始数据最后只留下 29.43%）。

我们的参考门槛可以定为：
- OVRL ≥ 3.0（推测可以再提到 3.2）；
- 没有多人叠音；
- 不含笑声、喊叫，这类片段留给情绪参考；
- 音量归一化，Emilia 用的是 −20 dBFS [28]。

**背景音乐和游戏声的影响：** 没有针对这一点的定量公开数据，只有方向性证据：
- CV3-Eval 有意保留含噪声的参考 [8]。同一个模型在它上面的中文 CER 明显高于干净的 Seed-TTS-eval：CosyVoice3-0.5B 为 3.89 对 0.81 [8][9]，IndexTTS2 为 2.25 对 1.01 [25][4]，VoxCPM2 为 3.65 对 0.97 [25][24]。两套测试文本不同，只能看方向。
- 阿里的闭源 Qwen-Audio-3.0-TTS 专门强调对含噪参考更稳 [30]，说明这是各家的普遍弱点（推测）。
- 实践上，分离后残留的 BGM 或枪声容易被当成音色的一部分复制出来（推测）。所以宁可要短而干净的片段，也不要长而脏的。

**每个说话人维护一个参考库：**
- 按说话人 ID 收集候选片段并打分，分数由三项组成：DNSMOS OVRL；与该说话人声纹中心的余弦相似度（防止分离错人）；时长落在 6–12 s 时加分。
- 保留得分最高的 3 条，有更好的片段就替换。
- 分数稳定后锁定，避免音色漂移。

**冷启动：** 新说话人还没有合格片段时，先用这句本身（至少 3 s 且过门槛），或者用同性别的中文预设音色；拿到好片段后再切换。D = 30–45 s 的缓冲通常够攒出第一段 6 s 的干净语音（推测）。

**条件缓存：**
- IndexTTS 只缓存「上一个」说话人的条件，换人就要重算 [6]。多人交替发言时，要改成按说话人 ID 存的字典缓存（推测是小改动）。
- CosyVoice 有 `add_zero_shot_spk`，可以按 ID 注册后复用 [12]。
- Qwen3-TTS 有 `create_voice_clone_prompt` [18]。

### 3.5 音色参考与情绪参考分开给

**只有 IndexTTS2 / 2.5 原生支持。**
- 论文称实现了情绪与说话人身份的解耦：音色取自音色参考，情绪取自风格参考 [4]。
- 代码里 `emo_audio_prompt` 单独经过 w2v-BERT，用 `emo_alpha` 调强度。
- **注意：** 不传情绪参考时，代码默认拿音色参考当情绪参考，强度 1.0 [6]。所以必须显式传入当前这句（分离后）的原声，否则情绪会跟着那段中性的音色片段走。

**跨语种情绪迁移：**
- 2.5 论文称，在没有目标语种情绪训练数据的日语、西语上也能迁移情绪 [3]。
- 英语情绪参考 → 中文输出没有公开数字。
- 风险（推测）：英语原声当情绪参考，可能顺带把英语韵律带进中文。需要做 A/B 对比口音分和情绪匹配分，三种配置是：用原声作情绪参考；用情绪识别结果转成 8 维情绪向量 [1]；完全不给情绪。

**其他模型都做不到用两段音频分开给：**
- CosyVoice3 是音色参考加文字指令 [12]；
- VoxCPM2 是音色参考加文字描述 [26]；
- Qwen3-TTS Base 没有情绪控制 [18]。

## 4. 本机落地的风险与绕法

1. **显存超预算。** ASR、翻译、TTS 挤在 13 GB 里，TTS 一旦超过 5–6 GB，Windows 可能把显存溢出到共享内存，结果是变得极慢，而不是直接报 OOM（推测）。#585 在 12 GB 卡上 RTF 13 的现象与此吻合，但原因没有确认 [34]。上线前严格按预算，用 nvidia-smi 盯住峰值。
2. **sm_120 与 torch 版本。**
   - CosyVoice 仓库锁的是 torch 2.3.1；换成新 torch 加 transformers 5.x 会输出乱码 [14]。绕法：用 torch 2.7+/cu128，同时保持仓库原本的 transformers 4.51.3（推测可行，需验证）。
   - IndexTTS 要求 CUDA 12.8+ [1]。它自带的 BigVGAN CUDA 核默认开启 [6]，编译需要 nvcc 并修改目标架构 [35]；WSL 里没有 nvcc，要显式设 `use_cuda_kernel=False`。
3. **vLLM。** WSL 里现成的 vLLM 是 0.26，而 IndexTTS-2.5 的配方要 0.27+ [31]。不动现有 venv，另建一个。沿用本机已知设置：`VLLM_USE_V2_MODEL_RUNNER=0`、`VLLM_USE_FLASHINFER_SAMPLER=0`；INT8 W8A8 在这张卡上不可用。如果翻译也用 vLLM，两个实例要分好 `gpu_memory_utilization`。
4. **kernel 启动开销与短句。** 优先用 CUDA Graph 的实现（见 3.3）；短句合并成一次推理。
5. **合规。** 克隆主播或发言人的音色需要授权；AI 合成内容要按国内规定做标识（具体条款本报告未核）。rubberband 是 GPL，闭源分发需要买商业许可 [40]。
