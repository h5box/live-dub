# live-dub 调研：同传式混音、克隆参考音频提取、唱歌/音乐/掌声检测

> 2026-09-29 调研，09-30 按作者决定改版：同传式（原声压低、中文克隆配音盖在上面）；先做英语，全部在本机跑。本版取代上一版。
> 数字都注明了出处和测试硬件。标「推测」的是本文的推断，标「起步值」的是经验参数，要靠听测定。

## 1. 结论先行

### 1.1 压低原声

**主力用按时间轴预先算好的增益包络，sidechain 只作可选的细调。**
- 每句配音的起止事先都知道，所以直接在 Python 里逐采样生成增益包络（在 dB 域做升余弦过渡），ffmpeg 只负责编解码。
- 包络的好处：能在配音开口前就压到位；不会跟着 TTS 的音节忽高忽低；结果可复现。
- `sidechaincompress` 只能跟在配音后面反应（默认 attack 20 ms、release 250 ms）[3]。
- 不要用 ffmpeg 的 `volume`（`eval=frame`）做包络：它每帧才取一次值，包络会变成台阶[3]。

**压什么：**

| 方案 | 做法 | 定位 |
|---|---|---|
| **B2（首选）** | 只压分离出的人声轨，伴奏原样 | Netflix 规定压的是原声对白（OV），画外的 OV 直接去掉[1]，说明专业 VO 后期是在分轨上操作的，B2 就是在逼近这种做法。人声只衰减不删除，分离伪影会被配音盖住。分离模型 Kim 反正要为提取参考音频而加载（1.3） |
| B1（首选的备选，不占显存） | 分频压：原声 250 Hz–5 kHz 压 −18 dB，低于 250 Hz 压 −6 dB，高于 5 kHz 压 −10 dB（起步值） | 游戏和 BGM 的低频、高频大体保留，思路和 TrackSpacer 这类「频谱闪避」插件一样[4]。分频用线性相位 FIR（反正有 D 秒延迟，不在乎几毫秒）：高频 = 原信号 − 低频，可以完美重建 |
| B0（只作调试基线） | 整条原声压 −12 dB | Netflix 专利给的范围是 6–12 dB[2]，达不到 VO 指南的 15–19 dB[1]，在同音色的情况下偏浅 |

B2 是否转正，看实测：Kim 在并发下 RTF ≤ 0.15、显存 ≤ 3 GB 就用 B2，否则用 B1。

**参数（起步值）：**

| 参数 | 值 | 依据 |
|---|---|---|
| 原声人声压多少 | −18 dB（B2 作用于人声轨；B1 作用于 250 Hz–5 kHz 频段） | Netflix VO：比配音低 15–19 dB[1] |
| 伴奏（B2） | 0 dB；配音被游戏声盖住时再压 2–3 dB | 起步值 |
| 压下 | 250 ms；包络提前开始，在配音开口时刻正好压到底 | 专利默认 250 ms（范围 100–500 ms）；专利也允许新音频晚约 1 s 才进来[2] |
| 恢复 | 从「配音结束」和「原句结束」里较晚的那个再过 150 ms 开始，用 1.0–1.5 s 升回 | 专利默认 2 s（范围 1–2.5 s）[2]；Netflix 要求起伏平滑，不能让人听出音量掉了一截[1] |
| 句间空隙 < 1.5 s | 保持压低，不回弹 | 起步值 |
| 原声前导 | 默认不加（配音对齐开口）；可选 0.5–1 s；多人交替或抢话时不加 | Netflix：画内每段第一句 OV 最多先放 1 s；对话重叠时不给每个新说话人加前导，否则会乱[1] |
| 让原声「退后」 | 压低期间，原声 4 kHz 以上再压 3 dB；可以加一点短混响 | 推测，依据见下文[7] |
| 配音本身 | 干声、居中；不改音高和共振峰；逐句响度与原句人声的短时响度对齐 | [6] |
| 节目整体 | −16 LUFS ±1；编码前真峰值 ≤ −1 dBTP | [39][41] |
| 配音超长 | 依次：翻译时控字数 → 用能控时长的 TTS（IndexTTS2 能指定 token 数[37]）→ 变速 0.9–1.15 倍（rubberband，`formant=preserved`[3]）→ 占用后面的静音 ≤ 0.5 s → 重译 | 起点宁晚勿早：声音超前 45 ms 能察觉，滞后 125 ms 以内察觉不到[38] |

**同一个音色的两个声音叠在一起，会不会像回声或串音？**

不会是回声：回声要求同一段声音延后重复，这里两边说的内容不同。真正的风险是「同一个人同时说两句话」那种串音感。依据：
- 两个声音同时说话时，干扰者和目标是同一个人时最难听清，异性最容易；电平差本身能帮听者分开两个声音[5]。
- 基频相差 2 个半音以上，或声道长度比 ≥ 1.08，都能帮助分开[6]。但改配音的音高会毁掉克隆效果，不采用。
- 业内 VO 本来就要求配音演员的年龄、性别与原说话人相近[1]，靠 15–19 dB 的电平差和起音错开来区分。

所以缓解手段按优先级是：
1. **压得够深**：原声的人声频段至少比配音低 18 dB。
2. **起音不重叠**：配音开口前原声已经压到底，不让两个声音在相近电平下同时起音。
3. **让原声「退后」**：原声变暗一点、带一点混响；配音保持干、近、居中。依据是：两个声音听起来来自不同位置时，互相干扰明显减轻[7]；从「左右位置」推到「远近」是推测。
   - 不建议把两者左右声像拉开：手机外放多是单声道，这个区分会消失（推测）。
4. **参考音频要干**：零样本 TTS 会连同提示音频的情绪和声学环境一起复现[8]。参考里带混响或 BGM，配音听起来就像「同一个房间里的第二个人」。
5. **语言不同本身有帮助**：两个人同时说话时，母语干扰比外语干扰更严重[9]。不过对听得懂英语的观众，这个好处会打折扣（推测）。

### 1.2 分块处理（B2 用）
- 块长用 Kim 原生的 8 s（44.1 kHz 下 352800 个采样点[11]），步长 4 s，流式重叠相加。
- 加窗用 MSST 的做法：每块两端各有块长 1/10 的线性淡入淡出，叠加后按窗口权重之和归一化[10]。
- 某个采样点等所有覆盖它的块都算完才输出，所以结果和整段离线处理一致，延迟约为 8 s 加推理时间。
- 速度：T4 上 Kim fp16 单遍 RTF 约 0.10[12]。在 5060 Ti 上带 50% 重叠，推测 RTF 在 0.05–0.15。

### 1.3 克隆参考音频：「先筛后修」，只做不会改内容的轻处理

**首选链路**（每段 3–15 s）：
1. 用 pyannote community-1 分出说话人，只取单人说话、没有重叠的段落；发布会上每人各取各的[14]。
2. 用 1.4 的检测结果排除掌声、音乐、笑声段。
3. 用 Brouhaha 给每段打 SNR 和 C50（衡量混响，越高越干）分[15]，按本机样本的分位数取靠前的段落，不预设绝对阈值。
4. 有 BGM 或游戏声时，用 Kim Mel-RoFormer 取出人声（MIT）[16]。
5. C50 偏低时去混响：用 anvuew 的 Mel-RoFormer 去混响模型（GPL-3.0）[17]，或者 WPE（nara_wpe，MIT，CPU 跑，经典算法，不会凭空生成内容）[18]。
6. 还有残余噪声的话，用 MossFormer2_SE_48K 降噪（Apache-2.0）[19]。
7. 校验：处理后与该说话人的声纹相似度不能下降，DNSMOS/NISQA 分要提升，ASR 要能正确转写；不满足就退回未处理的版本。每人保留最好的 3 段，遇到更好的就替换。另外尽量选语气平稳的句子，因为情绪也会被 TTS 复现[8]。

**备选**：Sidon、UniPASE 这类生成式修复，只在找不到干净段时用，而且必须过相似度校验[20][21]。

**不用**：
- Resemble Enhance：依赖 deepspeed，也不再维护[22]。
- Sucial 去混响：不可商用，而且是用歌曲训练的[23]。
- SAM Audio：显存 11 GB 起步[24]。

### 1.4 唱歌/纯音乐/掌声检测

**首选**：用 AudioSet 弱标签的标注模型滑窗跑（EfficientAT mn10_as，4.88 M 参数、mAP 0.471、MIT[25]；也可以用 PANNs 或 BEATs），取 Singing、Music、Speech、Applause、Clapping、Cheering、Laughter 这几类的概率。

**判断唱歌必须用弱标签模型**：AudioSet 的强标注（帧级）里，音乐段只标「Music」，没有再细分[26]，用它训练的帧级模型分不出「在唱歌」还是「纯伴奏」。

**辅助手段**：
- PretrainedSED 给出 40 ms 帧级结果，用来精确定位掌声和说话的边界[27]。
- 音乐段里 ASR 吐出来的字多半是幻觉，一律丢掉。
- 如果 ASR 选了 SenseVoice，直接用它输出的 BGM、Applause 标签[28]。
- inaSpeechSegmenter 能做语音/音乐/噪声分段（MIREX 2018 语音检测第一，MIT）[29]。

**规则（起步值）**：
- 连续 ≥ 5 s 检测到唱歌，就进入歌曲段；连续 5 s 没检测到才退出。
- 纯音乐或掌声、且没人说话 → 不配音；掌声和说话重叠 → 照常配音。
- 利用 D 秒延迟做前后各 5 s 的平滑，不必只看过去。
- 界面上留一个「歌回模式」手动开关。

## 3. 各候选要点

### 3.1 压低：业内依据
- **Netflix 非虚构类配音指南**[1]：
  - 画外的 OV 全部去掉。
  - 画内每段第一句先放最多 1 s 的 OV，再压到比配音低 15–19 dB（约为 OV 积分响度 −10 LUFS）。
  - 压低要平滑；配音和 OV 同时结束。
  - 笑、哭这类非语言声不配音，但要留在混音里。
  - 对话重叠时不给每个新说话人加 OV 前导。
  - 配音演员的年龄、性别要与原说话人相近。
- **Netflix 专利 US11430485B2**（2019-11 优先权，涵盖 lektoring 这种画外音译配）[2]：
  - 原声压 6–12 dB；压下 100–500 ms（默认 250 ms），恢复 1000–2500 ms（默认 2000 ms）。
  - 新音频可以晚约 1 s 才进入。

  两份文件放在一起看：给旁白或描述让路，压 6–12 dB 就够；要让原声对白退成背景，得压 15–19 dB。
- **进阶做法**：用配音的频谱来决定原声每个频段压多少（TrackSpacer 用 32 段 EQ[4]）。好处是配音停顿时原声能自然冒出来；代价是原声会随音节起伏，需要听测。
- **响度参考值**：
  - EBU R128：−23 LUFS，直播允许 ±1 LU，真峰值 ≤ −1 dBTP[39]。
  - 广电 GY/T 282-2014（电视）：−24 LKFS ±2 LU，真峰值 ≤ −2 dBTP[40]。
  - AES TD1008：流媒体语音 −18 LUFS[41]。
  - B 站直播：没找到官方公开的数值。
- **两个 ffmpeg 的坑**：
  - 不要在直播输出上用 loudnorm 的单遍动态模式。它本质是自动增益，内部升采样到 192 kHz，带 100 ms 前瞻[3][42]。
  - `alimiter` 默认 `level=enabled`，会把输出拉回 0 dB，必须关掉[3]。

### 3.2 分离模型（精简）
- **MVSEP 榜首**：BS Roformer 124 bands（2026-07，12.33）只能在 MVSEP 站内用，没有公开权重[30]。
- **Kim**：公开权重里，速度、质量、许可三方面最平衡。BS-RoFormer 慢一倍、权重许可不明[12][35]。
- **工具**：
  - python-audio-separator 0.47.0（2026-08-27）：支持 fp16 和局部 torch.compile，以 PyTorch 2.13 为验证基线[13][43]。
  - MSST：2026-07 发了框架论文[44]。
  - Demucs：原仓库 2025-01 已归档[32]。
  - UVR5 GUI：正式版停在 2023-09[45]。
- **影视三轨模型的一个特点**：常规数据训练出来的三轨模型会把笑声、尖叫分到「音效」轨[46]。对 B2 无害（这些声音留在伴奏里，不被压）；但提取参考音频时要注意，「对白轨」不等于主播的全部声音。

### 3.3 参考音频：为什么「先筛后修」
- **发布会**：讲者多半用近讲话筒，掌声多出现在句与句之间，所以直接排除掌声段，比去掉掌声稳。MSST 里的人群噪声分离模型 SDR 只有 5.99[31]。大厅混响先用 C50 挑出直达声多的段落，再决定要不要去混响[15]。
- **游戏/BGM**：先用 Kim 取人声，再测一次 SNR 和 C50。
- **去混响模型对演讲语音的效果要实测**：anvuew 的模型用独唱/人声训练[17]，Sucial 的用歌曲训练[23]。WPE 是线性预测，不会生成新内容[18]。
- **生成式修复**：Sidon（多语言，ICASSP 2026）、UniPASE（URGENT 2026 客观评测第一名的混合系统用的就是它）效果强，但可能改音色[20][21]。
- **速度与显存**：
  - 只在新说话人出现时处理几段，模型按需加载、用完释放。
  - Kim 在 T4 上处理 15 s 约 1.5 s（按 RTF 0.10 推算）；pyannote 在 H100 上约为实时的 1%[14]。
  - 在 D 秒延迟内攒出第一段参考应该来得及（推测）。

### 3.4 事件检测：补充
- AudioSet 弱标签里，Singing 有 42,493 条标注（子类包括男声、女声、童声、合唱、说唱等），Applause 有 2,247 条[26]。
- 强标注有 456 个标签（2021-05），但音乐段只标「Music」[26]。
- 开放词表的 FlexSED（2025-10，MIT）、COSED（Meta，2026-09，未见代码）可以用自定义文本查询[47]。
- Whisper-AT 只支持到 large-v2[47]。

## 4. 在本机落地的风险与绕法
1. **sm_120 遇上钉死旧版本的依赖**：bandit-v2 钉死 torch 2.0.0+cu118[33]；DeepFilterNet 在 torchaudio ≥ 2.9 上 import 失败[36]；Resemble Enhance 依赖 deepspeed[22]；已有分离类应用在 5060 Ti 上报「no kernel image」的案例[49]。绕法：每个工具一个 venv，先装 cu128 的 torch，再用约束文件装其他依赖（防止 torch 被悄悄换掉）；启动时检查 `torch.cuda.get_arch_list()` 里有 sm_120。
2. **TensorFlow 系工具**（inaSpeechSegmenter、YAMNet）：TF 从 2.11 起不再支持 Windows 原生 GPU[48]。放进 WSL，或者直接用 CPU 跑（模型小，推测够用）。
3. **pyannote 4.x**：解码依赖 torchcodec 和 ffmpeg[14]，在 Windows 上容易和 ffmpeg 版本冲突（SAM Audio 的教程也踩过 torchcodec 的坑[24]）。
   - 直接把内存里的波形传给它，绕过解码。
   - 模型在 HF 上授权下载后离线用。
   - 关掉遥测。
4. **torch.compile**：在 Windows 原生上需要社区版 Triton（推测）。分离服务可以放进 WSL，权重放在 WSL 自己的盘上。
5. **显存**：B2 常驻 Kim（推测 2–3 GB）；参考链路的各个模型按需加载、用完释放；SAM Audio 不进实时链。
6. **许可**：anvuew 去混响是 GPL-3.0；Sucial 是 CC BY-NC-SA；pyannote community-1 是 CC BY 4.0，要署名。自用没问题，将来分发或商用要复核。

## 5. 建议在本机实测的清单

| # | 测什么 | 样本 | 指标 | 通过线（建议值） |
|---|---|---|---|---|
| 1 | 压低方案 | 英语发布会（多人、掌声、混响）、英语游戏直播（BGM、音效）、英语杂谈，各 3 段，每段 1–2 min。组合：B0/B1/B2 × 压 12/15/18/21 dB × 原声是否做「退后」处理 × 是否加 0.5 s 前导 | 盲听按 1–5 分打：串音/回声感、配音可懂度、背景自然度、总体偏好 | 选出串音感 ≤ 2、总体最高的组合 |
| 2 | 包络 vs sidechain | 同上 | 是否忽大忽小；配音起音处有没有「两个声音」 | 包络不比 sidechain 差 |
| 3 | B2 实际压了多少 | 干净英语人声混入游戏/BGM（合成样本） | 输出里原声残留相对原电平低多少 dB；对输出做英语 ASR 的识别率 | 实际压低 ≥ 15 dB |
| 4 | B2 开销 | 连续 30 min，与 ASR、TTS 同时跑 | RTF、峰值显存、单块耗时 P99 | RTF ≤ 0.15，显存 ≤ 3 GB，P99 < 4 s |
| 5 | 参考音频 | 8 位英语说话人（含一场多人发布会），每人 10 段 3–15 s 候选；每一级处理都留输出 | SNR/C50、DNSMOS、声纹相似度；克隆出的中文配音的相似度 MOS 和 CER；单段耗时和显存 | 处理后相似度不下降；克隆 MOS 高于未处理的；单段 ≤ 2 s、显存 ≤ 3 GB |
| 6 | 多人说话人 | 2 场人工标注过的发布会 | DER；参考音频分错人的次数 | 分错人 0 次 |
| 7 | 事件检测 | 人工标注 90 min：歌回、BGM 杂谈、发布会掌声、游戏 | Singing/Music/Applause 按 1 s 粒度算 F1；10 s 以上歌段的召回率；ASR 幻觉被拦下的比例 | 歌段召回 ≥ 95%，误判 ≤ 2% 时长 |
| 8 | 响度 | 30 min 成品（AAC 编码后） | 积分响度、真峰值、逐句配音与原句的响度差 | −16 ± 1 LUFS；真峰值 ≤ −1 dBTP；逐句差 ≤ 2 LU |
