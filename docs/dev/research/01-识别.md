# live-dub 调研：语音识别（ASR）与说话人分离

> 调研日期 2026-09-29，已按 09-30 的需求更新，替换上一版。本版的前提是：先做英语；配音采用同传式，按说话人克隆音色；全部在本机跑，可用显存约 13 GB。只做了网络调研，没有实测。方括号里的编号对应第 6 节的来源；标「推测」的是推断，不是已有数据。

## 1. 结论先行

| 环节 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 英语识别 | **Parakeet-TDT-0.6B-v2** | Qwen3-ASR-1.7B 加对齐器；Whisper large-v3-turbo | 0.6B 参数，省显存，速度极快（RTFx 3386）；英语榜 WER 6.05，自带词级时间戳 [5][6]；和分离模型同属 NeMo 栈 |
| 时间戳 | Parakeet 原生词级时间戳（FA-Bench 词边界 MAE 80.5 ms）[4] | 句尾不准时，用 Qwen3-ForcedAligner（32 ms）或 NFA（47 ms）精修 [4] | Whisper 原生时间戳 MAE 123 ms，而且整体偏早约 150 ms，不用 [4] |
| **说话人分离（重点）** | **Nemotron-3-Diarization**（2026-09-23 发布，流式 Sortformer，最多 8 人）：用 1.04 s 延迟档在线出标签，再用全局声纹库兜底 | pyannote community-1，放后台滑窗重聚类；Streaming Sortformer v2.1（最多 4 人） | 原生按块增量；靠「到达顺序说话人缓存」让说话人 ID 跨块保持一致 [21][22]；远场 AMI SDM 上 DER 11.1–13.0%，上一代 v2.1 为 17.8–20.6% [21][23] |
| 声纹嵌入 | 在线关联用 **CAM++**（7.2M 参数，Vox1-O EER 0.65%）；挑克隆参考、评估克隆相似度用 **WavLM-Large SV**（EER 0.431%） | ERes2NetV2（0.61%）、TitaNet-L（0.66%）、ECAPA（0.80%） | CAM++ 小而准 [30]；WavLM-SV 最准，也是 Seed-TTS-eval 算音色相似度（SIM）用的模型 [35][36] |
| VAD / 唱歌 | Silero VAD v6.2；FireRedVAD 的语音/唱歌/音乐三分类 | AST-AudioSet 分类器 | Parakeet v2 官方说连歌词也能稳定转写 [6]，所以唱歌必须单独判别 [18][19][20] |
| 日/韩（次要） | Qwen3-ASR-1.7B + Qwen3-ForcedAligner | Whisper-turbo | FLEURS ja 5.20、ko 2.57（CER），对齐器支持日韩 [2]；第三方日语口语小样本测试排第一 [16] |

要点：
- **显存（推测）**：识别加分离合计约 3–4 GB，给本地翻译和克隆 TTS 留出约 9 GB。
  - Parakeet v2 约 2–3 GB；Nemotron-3-Diarization 只有 99M 参数，不到 1 GB；CAM++ 可忽略。
  - 如果改用 Qwen3-ASR-1.7B 加对齐器，要多占 4–5 GB。
- **不必对整条流做人声分离**：同传式配音只是把原声压低，所以只在挑克隆参考时，对候选片段离线跑一次分离就够了，能省下一块常驻显存（建议）。
- **说话人身份分三层**（设计建议）：
  - 在线层：Nemotron-3 用 1.04 s 档给每一帧分配槽位。
  - 声纹层：每句话算一次嵌入，和声纹卡比对；槽位到全局 ID 的对应用匈牙利匹配加阈值。
  - 后台层：每 1–2 分钟对累计的嵌入重新聚类，只修正之后的句子。
  - 主讲人可以提前登记声纹，或由操作员确认；观众提问先用通用音色，等干净语音累计够了再克隆。
- **时延**：分离 1.04 s，加上识别、翻译、TTS，单句仍在 D 以内。30.4 s 档加上句长就会吃光 D，只能放后台（推理）。

## 3. 各候选要点

**3.1 英语识别**
- **首选 Parakeet v2。**
  - 英语专用，0.6B 参数，自带标点和词级时间戳，单段最长 24 分钟 [6]。
  - 在 FA-Bench 上，它自己出文本时的 WER 好于 Whisper；词边界 MAE 80 ms，在 150–200 ms 的目标之内 [4]。但词尾时间是估算出来的 [42]，句尾误差要实测，不够准时用对齐器精修。
  - 非语音段上的幻觉没有公开数据。
- **Qwen3-ASR-1.7B**：精度同档，还能覆盖日韩。但要外挂对齐器，显存会紧张。先作为 A/B 对手。
- **Whisper-turbo**：Windows 原生跑起来最省事，作为兜底。
  - 要避开 CTranslate2 在 sm_120 上的 int8 问题 [14]。
  - 要防静音、音乐段上的幻觉 [15]。办法：只把 VAD 判为语音的片段送进去，关掉 condition_on_previous_text，再加一张幻觉短语黑名单。
- **Granite 4.1 2B-plus 和 multitalker-parakeet**：一个自带说话人归属，一个专门处理重叠 [8][10]。可以拿「抢话」样本试试。但它们给出的都是局部说话人标签，全局 ID 仍要靠 2.2 节的方案（推测）。
- **日/韩（次要）**：用 Qwen3-ASR-1.7B 加 Qwen3-ForcedAligner，对齐器自报日语 42.4 ms、韩语 37.2 ms [2]。Nemotron-3-Diarization 的训练语种里没有明确列出日韩 [21]，做日韩前要先实测。

**3.2 VAD 与唱歌**
- Silero v6.2：MIT 许可，每个 30 ms 块在 CPU 上不到 1 ms。官方承认，音色像人声的乐器和极高音调仍会误报 [18]。
- FireRedVAD：在 FLEURS-VAD-102 上自测 F1 97.6、误报 2.7%，Silero 在同一测试里是 95.9 和 9.4%；它还能把音频分成语音、唱歌、音乐三类 [19]。
- AST 分类器：带 AudioSet 的 Singing、Music、Video game music 等标签，可以作为第二意见 [20]。
- 判定为唱歌的段落不配音。

**3.3 说话人分离（重点）**

**两类机制的差别**
- 端到端流式（Sortformer 系）：
  - 按 80 ms 一帧，直接给每个槽位输出独立的说话概率，天然能标出重叠。
  - 靠「到达顺序说话人缓存」在块与块之间保持每个槽位代表同一个人，所以 ID 跨块稳定。
  - 缺点是槽位数量有上限 [21][22]。
- 「分段 + 嵌入 + 在线聚类」（diart；自己把 pyannote 改成滑窗也属于这一类）：
  - 不限人数，但身份完全靠嵌入判断，**说话人混淆是主要误差**。
  - diart 在 5 s 延迟下，说话人混淆比离线多出 100–160%，要约 5 分钟后才接近离线水平 [28]。

**重叠说话**
- 两类方案都能检测重叠：
  - Sortformer 的评测都包含重叠语音 [22]；
  - pyannote 的分段模型每帧最多标 2 人 [27]；
  - community-1 还能给出同一时刻只一人的 exclusive 结果 [26]。
- 没有找到专门在重叠段上打分的公开数据。
- 配音侧的建议：重叠处只配主说话人；重叠段不进声纹库，也不拿来当参考音频。

**主持人与嘉宾频繁切换**
- 端到端类按帧判断，对短轮次更友好：CALLHOME 是轮换很快的电话对话，Nemotron-3 在上面 2 人 DER 为 6.98% [21]。
- 聚类类在短片段上算出的嵌入噪声大：diart 只有在一个人说话够长时才更新质心，短轮次根本用不上 [28]。
- 一项独立基准发现，误差主要来自漏检和起止点不准，和片段长短关系不大 [25]。

**观众提问（远场、音质差、陌生人多）**
- 远场：Nemotron-3 在 AMI SDM 上 DER 11.1–13.0，好于 community-1 的 19.9 和 v2.1 的 17.8–20.6 [21][26][23]。
- 最大的风险是人数：
  - Nemotron-3 最多 8 人，DIHARD III 上 5–9 人时 DER 27.58 [21]；
  - v2 系最多 4 人，5 人以上时 DER 22.7 [25]。
  - 槽位满了以后，新来的人会被丢掉或者并进已有的槽位（推测；论文说 4 人版只跟踪最主要的 4 个人 [22]）。对克隆来说，这等于把观众的声音混进了主讲人的声纹卡。
- 对策（设计建议）：
  - 每句话算嵌入，和它所在槽位的声纹卡比余弦相似度；低于阈值就当作新的人，或者归到「观众」通用音色。
  - 主讲人提前登记声纹（用开场几分钟或往期视频），然后锁定。
  - 后台重新聚类，修正合并和拆分。

**其他方案**
- diart：机制清楚，可以换用 WeSpeaker、ECAPA、TitaNet 的嵌入 [28]。但依赖陈旧，只借用它的算法，放在 Nemotron-3 或 community-1 的输出之上。
- DiariZen：离线最准，但权重不能商用 [29]，只适合给测试集做预标注。
- Nemotron-3-Diarization 才发布 6 天，社区里还没有使用经验。

**3.4 声纹嵌入与克隆参考音频**

**选型**
- 在线关联：每句话都要算，要求快。用 CAM++ 或 ERes2NetV2。在更难的 CN-Celeb 上，它们的 EER 为 6.1–6.8%，ECAPA 是 8.01% [30]。
- 挑参考音频、评估克隆效果：次数少，要求准。用 WavLM-Large SV [35]。它和 Seed-TTS-eval 计算 SIM 用的是同一种模型 [36]，这样挑参考和验收克隆用的是同一把尺子。
- 公开资料里都没有远场条件下的 EER。所以只用 3 s 以上、没有重叠、质量合格的片段算嵌入 [32]。

**挑参考音频的流程（建议）**
1. 候选：这个全局 ID 下的 exclusive 片段，没有重叠，没有笑声和唱歌，时长 ≥3 s。
2. 离线跑人声分离，拿到干净人声。
3. 用 DNSMOS 打分（本地 ONNX 运行，不需要参考音频的语音质量评分），取总分 OVRL 高的片段 [38]。
4. 算每个片段和说话人质心的相似度，剔除离群片段（多半是分离错误）。
5. 按 ASR 的词级时间戳在词边界切开，附上逐字转写，作为 TTS 的 prompt 文本。
6. 选定后锁定一段时间，避免中途音色漂移。
7. 新说话人的头几句，可以先用这一句自己的音频当参考（需要 TTS 组确认可行）。
8. 克隆出来的音频用 WavLM-SV 和真人片段比相似度，低于阈值就报警。这一步还能反查出分离错误。

**许可**：在 VoxCeleb 上训练的权重跟随数据集，为 CC-BY-4.0 [32]；TitaNet 也是 CC-BY-4.0 [34]；SpeechBrain 的 ECAPA 是 Apache-2.0 [33]；ReDimNet 是 MIT [37]。

## 4. 本机落地风险与绕法（5060 Ti · sm_120 · Windows / WSL）

1. **NeMo 栈（Parakeet v2、Nemotron-3、Sortformer、TitaNet）只能在 WSL 里跑。**
   - NeMo 不支持 Windows 原生安装 [17]。NeMo Speech v3.0 要求 Python 3.12+、PyTorch 2.7+，推荐 CUDA 13 [7]；Nemotron-3 要求 NeMo 3.0 和 Linux [21]。
   - 利好：Nemotron-3 在 Blackwell 架构的 RTX PRO 5000 上有实测速度 [21]，它和 5060 Ti 同属 sm_120（推测）。它还有 transformers 流式接口 [21]，也许能在 Windows 上跑（推测）。
   - 做法：单独建 venv，和现有的 vLLM / cu128 环境隔开；模型放在 WSL 自己的盘上。
2. **pyannote 4 在 Windows 上**：它用 torchcodec 解码音频，常见报错是找不到 FFmpeg 共享库的 DLL [31]。办法是放到 WSL 里跑，或者自己解码后把 waveform 直接传进去。
3. **diart**：依赖旧（pyannote<3.1、Python ≤3.10）[28]，只借它的算法，不直接装。
4. **CTranslate2 / faster-whisper（兜底用）**：RTX 50 系上 int8 曾报 CUBLAS_STATUS_NOT_SUPPORTED；CTranslate2 4.7.0（2026-02）起修复。要么装 ≥4.7，要么先用 float16 [14]。
5. **ONNX Runtime / sherpa-onnx**：官方 GPU 版直到 1.28 左右（2026-07）才加上 sm_120 支持；sherpa-onnx 的 CUDA 版还基于 ORT 1.22 [40]。CAM++、Silero 这类小模型直接用 CPU 版 ONNX。
6. **显存管理**：模型尽量放在同一个进程里，少开 CUDA 上下文，因为每个上下文都有固定开销（推测）。翻译如果走 vLLM，要调低 gpu_memory_utilization [39]。

## 5. 建议的本机实测清单

**样本**
- 英语为主，自建：
  - 3–5 场真实发布会或展示会，要带问答环节，每场 30–60 分钟；
  - 2 场多人联动或抢话的直播；
  - 1 场单人游戏直播，约 2 小时。
- 公开数据集：AMI（近讲和远场 SDM 两种）、VoxConverse（YouTube 视频，2 到 20 多人 [25]）。
- 真值：先用 DiariZen 或 community-1 离线预标注，再人工修正说话人；另抽 300 句人工标注起止时间。

| # | 测什么 | 指标 | 通过线（建议） |
|---|---|---|---|
| 1 | 句级说话人正确率（配音实际用的就是这个） | 每句取多数标签，和真值比 | 主讲人 ≥95%；观众的句子要么分到正确的新 ID，要么归入「观众」类，合计 ≥90% |
| 2 | 整场 ID 一致性 | 两个真实主讲人被并成一个 ID 的次数；同一个人被拆成几个 ID | 合并 0 次；拆分每人每小时 ≤1 次（后台能合回来） |
| 3 | 新说话人建档延迟 | 新的人开口后，要说多长时间才拿到稳定 ID | ≤10 s |
| 4 | DER / JER | 分别算无 collar 和 0.25 s collar 两种口径；按重叠段、2 s 以下的短轮次、远场问答段分别统计 | 比 community-1 离线结果退化不超过 30% |
| 5 | 嵌入模型 | 用自建数据做同人/异人对（近讲和远场分开），算 EER；对比 CAM++、ERes2NetV2、ResNet34-LM、TitaNet、WavLM-SV、ECAPA | 近讲 EER ≤3%；远场单独报告 |
| 6 | 自动挑克隆参考 | 和人工挑的比：克隆结果的 WavLM-SV 相似度，加 AB 听感 | 相似度不低于人工挑选减 0.02 |
| 7 | 英语识别 | WER；句级可用率（人工判断意思对不对）；Parakeet v2、Qwen3-ASR、turbo 三者对比 | 可用率 ≥90% |
| 8 | 时间戳 | 句首、句尾误差的 p90 / p99，以及平均偏移 | p90 ≤150 ms；p99 ≤300 ms |
| 9 | 幻觉 / 唱歌 | 30 分钟非语音里冒出的伪字幕句数；唱歌段的召回率 | 每 10 分钟 ≤1 句；召回 ≥95% |
| 10 | 全链路资源 | 识别、分离、嵌入和翻译、TTS 同时跑：峰值显存、各环节 RTF、单句 p99 时延 | 识别加分离 ≤4 GB；RTF ≤0.2；p99 ≤3 s |
| 11 | 长时间稳定性 | 连续跑 6 小时：崩溃、内存泄漏、ID 漂移 | 不崩溃；主讲人 ID 不漂移 |
