# 安装

## Windows 安装版（推荐）

从 [GitHub Releases](https://github.com/h5box/live-dub/releases) 下载 Windows 安装程序。
打开后按「设置向导」下载原生 CPU 识别模型和缺少的工具，选择容量足够的模型目录。
填写线上翻译接口并测试，最后播放内置测试片。无需手动安装 Python、Node.js、WSL。
模型约 0.8 GB，中断后点重试可续传；所有下载完成后先校验再使用。
安装版的设置、密钥、日志和历史保存在 `%LOCALAPPDATA%/LiveDub/`，更新程序不覆盖它们。
原生 ONNX 保留词级时间戳、标点和 TitaNet 声纹；识别热词增强目前仅 NeMo 支持。
配音仍需 WSL 2 和 NVIDIA 显卡，向导提供可选安装入口。

开发者从源码构建安装包：`uv sync` 后运行 `scripts/build_desktop.ps1`，需 Node.js、Rust/MSVC、FFmpeg。
GitHub 的 Windows installer 工作流可手动构建；推送版本标签会生成 Release。

整套东西分成两半：

- **本机这一半**（Windows 或 Linux 原生）：后端 `livedub.server`、拉流切块、处理器、播放器界面、本地翻译（llama.cpp）、可选的 MediaMTX。
  Python 依赖由 `uv sync` 装进项目的 `.venv`。
- **Linux 这一半**：识别服务（NeMo）和配音服务（vLLM-Omni + IndexTTS-2.5）只能在 Linux 上跑。Windows 上它们跑在 WSL 2 里，
  后端通过 `wsl.exe` 拉起它们；Linux 上就是本机。Windows 默认 ONNX 识别不使用这一半，配音仍使用。
  Linux 环境和模型放在 `~/live-dub/`。

装到哪一步都可以运行 `uv run python -m livedub.doctor`（或程序的「环境」页），看还缺什么。

## 1. 基础工具

| 工具 | 用途 | Windows | Linux（Ubuntu） |
| --- | --- | --- | --- |
| uv | 管 Python 和依赖 | `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 \| iex"` | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |
| git | 下载代码 | `winget install Git.Git` | `sudo apt install git` |
| FFmpeg | 切块、转码、读时间戳 | `winget install Gyan.FFmpeg` | `sudo apt install ffmpeg` |
| Deno 或 Node.js | yt-dlp 解 YouTube 的播放校验 | `winget install DenoLand.Deno` | 见 deno.com |
| Node.js | 构建界面 | `winget install OpenJS.NodeJS.LTS` | 见 nodejs.org |

winget 装完要重开终端，新装的命令才在 PATH 里。FFmpeg 不在 PATH 里也行，在 `settings.json` 的 `tools.ffmpeg` / `tools.ffprobe` 填完整路径。

## 2. WSL 2（只有 Windows 要）

1. 用管理员身份打开 PowerShell，运行 `wsl --install`，重启。
2. 第一次打开 Ubuntu 时建用户名和密码。
3. 在 WSL 里运行 `nvidia-smi` 能看到显卡就对了（有 N 卡、要配音时才需要）。**驱动只在 Windows 里装**，不要在 WSL 里另装 NVIDIA 驱动。

已经装了 WSL、有多个发行版时，在 `settings.json` 里用 `linux.distro` 指定用哪个。

## 3. 代码和 Python 依赖

```
git clone https://github.com/h5box/live-dub.git
cd live-dub
uv sync
```

`uv sync` 会按 `uv.lock` 装好后端要的包（FastAPI、PyAV、yt-dlp、streamlink 等），需要的话连 Python 3.12 一起装。
YouTube 改了页面导致拉不到流时，先升级 yt-dlp：`uv lock --upgrade-package yt-dlp`，再 `uv sync`。

## 4. 识别环境（必需）

Windows 默认 `asr.backend=onnx`：先构建、启动界面，在设置向导下载模型即可。
以下安装步骤用于 Linux 默认 NeMo；Windows 选择 NeMo 时需设置 `asr.backend=nemo`。

```
wsl -e bash scripts/linux/setup_asr.sh      # Windows：在项目目录里运行
bash scripts/linux/setup_asr.sh             # Linux
```

在 `~/live-dub/venv-asr` 建一个 Python 3.12 环境，装 CPU 版 PyTorch 和 NeMo 3.0，再从 Hugging Face 下两个模型到 `~/live-dub/models/`：
Parakeet-TDT-0.6B-v2（英文识别，约 2.4 GB）、TitaNet-L（声纹，约 100 MB）。一共约 6 GB，网络好的话十几分钟。
识别跑在 CPU 上，不占显卡，占约 6 GB 内存。

## 5. 翻译

二选一，也可以都装、开始时再选。

**本地**（要 NVIDIA 显卡，约 5 GB 显存）：

```
uv run python scripts/fetch.py all
```

下载 llama.cpp 的服务端（`tools/llama.cpp/`，按显卡和驱动选 CUDA 版本，没有 N 卡就下 Vulkan 版）和默认的翻译模型
Index-Translate-9B（IQ4_XS 量化，约 5.4 GB，放 `models/`）。也可以分开下：`fetch.py llama`、`fetch.py model index-9b`、
`fetch.py model hy-mt2`（腾讯 Hy-MT2-7B，备选）。已经有 llama.cpp 或 GGUF 文件的，在 `settings.json` 里写路径，不用重下（见 [配置.md](配置.md)）。

Linux 上的 llama.cpp CUDA 版要 glibc 2.38 以上（Ubuntu 24.04 起）；更老的系统请自己编译 llama.cpp，再在 `tools.llama_server` 填路径。

**线上**：打开程序的「环境」页，在「线上翻译」里填 DeepSeek 的 API key（[申请](https://platform.deepseek.com/api_keys)），
或者任何 OpenAI 兼容接口的地址、模型名和 key（通义、Kimi、OpenRouter、本机的 Ollama 都行）。点「测试」确认能用。
key 只存在本机的 `.secret/` 目录里。线上翻译整场用一个对话做上下文，DeepSeek 这类有前缀缓存的接口很便宜（一小时几毛钱）。

## 6. 中文配音（可选）

```
wsl -e bash scripts/linux/setup_dub.sh      # Windows
bash scripts/linux/setup_dub.sh             # Linux
```

要 NVIDIA 显卡，约 6.5 GB 空闲显存。装 vLLM 0.30.0 和 vLLM-Omni 0.30.0（`~/live-dub/venv-omni`），给 vLLM-Omni 打上
`dubsvc/omni/` 里的补丁（单遍按目标时长合成），再下 IndexTTS-2.5 和它要的四个辅助模型。约 20 GB。

配音服务第一次启动要 2–3 分钟（编译、捕获 CUDA 图），之后每句约 1 秒。在程序的「环境」页启动它；没开的话只出字幕。

两个备选后端（一般用不上）：`setup_indextts.sh`（IndexTTS 在进程内跑，慢一些）、`setup_voxcpm.sh`（VoxCPM2），装完要在
`settings.json` 的 `dub` 里改 `backend` 和 `python`，见各脚本开头的说明。

## 7. 输出到 OBS（可选）

```
uv run python scripts/fetch.py mediamtx
```

打开「输出到 OBS」后，带字幕和配音的画面会推到本机的 MediaMTX（只听 127.0.0.1），OBS 里加一个「媒体源」，
取消「本地文件」，输入 `rtmp://127.0.0.1:1935/live/livedub`。字幕烧进画面要用中文字体：Windows 自带微软雅黑；
Linux 要装 `fonts-noto-cjk`。编码优先用 NVENC，没有就用 x264（吃 CPU）。

**推流前请确认你有权转播这个内容，风险自负。**

## 8. 界面

```
cd app
npx pnpm install
npx pnpm build
```

构建出 `app/dist/`，后端会在 http://127.0.0.1:8090 托管它：`uv run python -m livedub.server --open`。

桌面程序另外要 [Tauri 的构建环境](https://tauri.app/start/prerequisites/)（Rust；Windows 还要 Visual Studio 的 C++ 生成工具）：
在 `app/` 里 `npx pnpm tauri build --no-bundle`，产物 `app/src-tauri/target/release/live-dub(.exe)`。它要留在项目目录里面
（往上找项目目录来起后端），或者设环境变量 `LIVEDUB_HOME` 指向项目目录。

## 常见问题

**YouTube 提示要登录（Sign in to confirm you're not a bot）**：一些网络出口会被 YouTube 拦。在「环境」页的
「YouTube 登录」中选择从浏览器读取（先在那个浏览器里登录 YouTube；Chrome 新版的 cookies 加密后 yt-dlp 不一定读得出），
或者用浏览器扩展导出一个 `cookies.txt` 并填上它的路径，保存后点「重试」即可，不用重启后端（也可以直接改
`settings.json` 的 `youtube` 两项，改完要重启后端）。这种情况连续试 3 次仍不行，本场就会停止并显示原因。
读浏览器时提示 `Could not copy Chrome cookie database`，是浏览器还开着（Edge、Chrome 关窗口后常驻后台，要在任务管理器里结束）；
提示 `Failed to decrypt with DPAPI`，是这个浏览器的加密方式读不了，改用导出的 `cookies.txt`（这种情况同样试 3 次后停止）。
「观看」页的播放器会直接显示这几种原因。

**国内下载慢**：

- Hugging Face：`HF_ENDPOINT=https://hf-mirror.com`（安装脚本和 `fetch.py` 都认）。WSL 里要在 WSL 的 shell 里设，
  比如 `wsl -e bash -c "HF_ENDPOINT=https://hf-mirror.com bash scripts/linux/setup_asr.sh"`。
- PyPI：`UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple`（PyTorch 的 wheel 仍从 download.pytorch.org 下）。
- GitHub（llama.cpp、MediaMTX）：`uv run python scripts/fetch.py --github-mirror <镜像前缀> llama`。

**显存不够**：先停掉别的占显存的程序；或者翻译改用线上（省约 5 GB），或者不开配音（省约 6.5 GB）。
「环境」页的显卡卡片会提示空闲显存够不够。

**字幕来不及 / 配音漏掉**：观看页的「字幕余量」是每句做好时离播出还剩几秒。经常低于 5 秒就把延时 D 调大（10–120 秒）。
YouTube 直播本身会晚到 10 秒左右，所以直播建议 D 不小于 30 秒。

**识别服务起不来**：「环境」页的识别卡片点「查看最近日志」（`logs/asr.log`）。最常见的是 WSL 里的环境没装完，
重新运行 `setup_asr.sh` 即可（它可以重复运行，已经下好的会跳过）。

**WSL 里的路径**：后端把本机路径换成 WSL 看到的路径（`D:\x` → `/mnt/d/x`）交给识别和配音服务，所以项目目录和场次目录要在
有盘符的磁盘上（不能在 `\\wsl$\...` 里）。
