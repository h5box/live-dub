# 接口

都只听 127.0.0.1。端口是默认值，可以在 `settings.json` 的 `ports` 里改（后端的 8090 固定）。

## 后端 `livedub.server`（8090）

界面只和它打交道（`livedub/server/app.py`，数据形状见 `app/src/api/types.ts`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/status` | 服务状态、显卡、提醒、当前场次、进程健康、锚点和字幕处理范围；`downloads` 各下载项的进度，`demo` 内置测试视频的路径（没有为 null） |
| GET | `/api/downloads` | 这台机器能下载的组件：名称、大约多大、可选来源 |
| POST | `/api/downloads/{key}` | `{source}`：开始下载或继续已暂停的；正在下载的换到 `source`。`source` 为空时自动选择，连不上就换下一个来源。下本地翻译模型时缺 llama-server 会一起下 |
| POST | `/api/downloads/{key}/pause` | 暂停正在下载的（已下载的部分保留），或取消还在排队的 |
| GET / POST | `/api/settings/downloads` | 下载位置、已下载多少、所在磁盘剩余，`elsewhere` 是在 `settings.json` 中另行指定了位置的模型（不计入、不移动）；POST `{dir}` 更改，已下载的模型排在正在进行的下载之后移过去，进度在 `downloads.move` |
| GET / POST | `/api/settings/history` | 观看记录的目录、场数、占用、其中视频缓存多少；POST `{keep}`（1–100）保留最近几场的视频缓存，更早的随即清理 |
| POST | `/api/settings/history/clean` | 清理所有场次的视频和配音缓存（进行中的这一场除外），保留字幕和记录 |
| GET / POST | `/api/settings/background` | `{run_in_background}`：关闭窗口后是否继续运行服务 |
| POST | `/api/window-closed` | 桌面程序的窗口关闭时发：没有在观看时停止各项服务（`run_in_background` 为 true 时不停）；之后界面重新连上 `/api/stream` 就作废 |
| GET | `/api/stream` | Server-Sent Events：`status` 每 2 秒；当前场次的 `event`（字幕、配音）和 `timing`（耗时）边写边推；换场时 `reset` |
| GET | `/api/configs` | 场景预设 |
| GET | `/api/models` | 翻译模型，以及每个在这台机器上能不能用、为什么 |
| GET | `/api/doctor` | 环境检查（同 `python -m livedub.doctor`） |
| GET | `/api/services` | 各服务是什么、在哪跑、端口、日志文件 |
| GET | `/api/services/{name}/log?lines=200` | 服务日志的最后几行 |
| POST | `/api/services/{name}/{start\|stop\|restart}` | 起停服务（`asr`、`mt`、`dub`、`mediamtx`）；可带 `{config, model}`：NeMo 识别服务按哪个预设的热词启动、本地翻译起哪个模型，预设不存在是 404；直播中只能 start，stop / restart 返回 409 |
| GET / POST | `/api/settings/online` | 线上翻译接口的设置；POST `{provider, base_url, model, api_key}` 写 `.secret/<provider>.json`，key 不回传 |
| POST | `/api/settings/online/{name}/test` | 用保存的设置发一个很小的请求，看能不能用 |
| GET / POST | `/api/settings/youtube` | yt-dlp 的登录：POST `{cookies, cookies_from_browser}`，下一场开始时生效 |
| POST | `/api/session/start` | `{preset, src, delay, dub, obs, mt_model}`：src 是链接或本地视频路径 |
| POST | `/api/session/stop` | 停止当前场次 |
| POST | `/api/session/priority` | `{pt}`：点播优先处理目标节目时间；直播与 OBS 输出不支持 |
| GET | `/api/sessions`、`/api/sessions/{name}` | 历史场次列表、一场的全部记录 |
| GET | `/api/sessions/{name}/subtitles.srt?language=both` | UTF-8 SRT；语言为 `zh`、`en`、`both`，时间从本场首帧算起 |
| DELETE | `/api/sessions/{name}?cache_only=true` | 只清理分段与配音缓存；默认删除整场；活跃场次禁止删除 |
| GET | `/api/sessions/{name}/media/index.m3u8` | 这一场的画面（HLS，每段带节目时间） |
| GET | `/api/sessions/{name}/media/seg_NNNNNN.ts`、`/clips/dub_NNNNN.wav` | 分段、配音 |

`app/dist` 构建好时，后端在 `/` 托管界面。

## 识别服务（8091，CPU）

Windows 默认 `livedub.asr` 原生 ONNX，路径为本机路径；NeMo 入口 `svc/asr_service.py` 在 Linux 一侧，
WSL 路径为 `/mnt/<盘符>/…`。wav 是 16 kHz 单声道，两者使用相同接口。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | `{"ok": true, "boost": [热词…]}`；模型没加载完是 503 |
| POST | `/asr` | `{"wav": 路径}` → `{"words": [{"w", "s", "e"}], "wall_s"}`，时间相对这个 wav |
| POST | `/embed` | `{"wav": 路径, "spans": [[s, e], …]}` → `{"emb": [[192 维]], "wall_s"}`，归一化的 TitaNet 声纹 |

一次只处理一个请求。NeMo 启动预设提供热词，变化时后端自动重启；原生 ONNX 当前不支持热词增强。

## 配音服务 `dubsvc/server.py`（8092，Linux 一侧，GPU）

模型常驻，一次只处理一个请求（串行队列），处理器自己按截止时刻排先后。

### `GET /health`

模型没加载完返回 503，出错返回 500（带错误），加载完：

```json
{"ok": true, "model": "IndexTTS-2.5", "bf16": true, "vram_mib": 6299, "impl": "vllm-omni 0.30.0 (patched target_s) …", "queue": 0}
```

### `POST /synthesize`

```json
{
  "id": "unit-00123",
  "text": "我们团队在监测研究里的 token 使用情况",
  "lang": "zhen",
  "spk_ref": "/mnt/d/live-dub/outputs/live/<场>/clips/ref_spk1_96000.wav",
  "emo_ref": "/mnt/d/live-dub/outputs/live/<场>/clips/unit_00123.wav",
  "target_s": 6.56,
  "out": "/mnt/d/live-dub/outputs/live/<场>/clips/dub_00123.wav"
}
```

- `lang`：`zh`，夹英文时 `zhen`。`spk_ref` 是这个说话人的音色参考；`emo_ref` 是这句的原声（语气参考），可以为 null。
- `target_s`：目标时长（原句开口到收口），null 表示按自然语速。服务**一遍合成就按它控时**：GPT 生成后按语义码长度算出自然时长，
  倍率 = target_s ÷ 自然时长，限制在 0.85–1.10（超出取边界，返回里 `clamped` 为 true），然后只跑一遍 S2M 和声码器。
- 输出 wav 首尾静音已裁掉（开头留 30 毫秒）。

返回：

```json
{"id": "unit-00123", "out": "…wav", "sr": 22050, "natural_s": 5.1, "factor": 1.1, "clamped": true,
 "audio_s": 5.6, "raw_s": 5.7, "wall_s": 0.9, "queue_s": 0.0}
```

单句超过 `--timeout`（默认 20 秒）返回 504，处理器按降级处理（这句只出字幕）。

默认后端（`--backend omni`）把请求转给打了补丁的 vLLM-Omni（8093，OpenAI 风格的 `/v1/audio/speech`，`extra_params.target_s`），
补丁在 `dubsvc/omni/`。

## 场次目录

`outputs/live/<时间>-<场景或 link / file>/`：

| 文件 | 内容 |
| --- | --- |
| `run.json` | 这一场的状态、参数、过程记录 |
| `config.json` | 开始时合成的配置（预设 + 这次的选项） |
| `anchor.json` | 锚点 {T0, p0, delay} |
| `source.json` | 源是否为直播；点播可提前处理 |
| `progress.json` | `{ranges, position, done}`；ranges 为已处理节目时间区间，跳转后可不连续 |
| `priority.json` | `{id, pt, segment}`；处理器在句子之间切换到请求位置 |
| `buf/` | 分段 `seg_NNNNNN.ts` 和 ffmpeg 的分段表 |
| `events.jsonl` | 每句一行：`{pt0, pt1, zh, en, spk, dub, gain}`；同一 pt0 再出现一次就是带上配音的版本 |
| `timing.jsonl` | 每句的耗时和余量；配音的结果（ok / late / skipped / failed） |
| `mt_api.jsonl` | 线上翻译每次调用的 token、缓存命中、耗时 |
| `clips/` | 音色参考、配音 |
| `ingest.log`、`processor.log`、`playout.log` | 各进程的日志（`.err` 是错误输出） |
